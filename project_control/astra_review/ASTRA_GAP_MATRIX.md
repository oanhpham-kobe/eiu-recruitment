### Reading the matrix

- Target references `A Rnn` resolve to A's source-cited requirement ledger; `A §n` to its design/verification sections. Evidence `E01` etc. resolves to the exact baseline source catalog below. `B Fnn` preserves finding provenance, not sole implementation proof.
- Effort **S/M/L/XL** is a comparative estimate for the row's bounded change or acceptance work, not calendar time and not additive across overlapping rows. KEEP/S commonly means retain plus focused verification; it does not commission a refactor. Estimates are **[INFERENCE]** based on interfaces and crossed invariants.
- Migration/re-proof **Low/Medium/High/Very High** includes interface/caller changes and evidence recreation, even when no business data moves. No cloud inventory is assumed. A High proof cost is often a reason not to replace a working invariant.
- Confidence: **H-source** = strong direct-source evidence, not runtime certification; **H-runtime(B)** = observed in Phase B and not rerun here; **M** = partial surface/operational evidence; **U-cloud** = current external state unknown. Structural KEEP remains conditional on normal acceptance proof.
- Dependencies identify row IDs or specific prerequisites, not a scheduled implementation DAG. No next-frontier task is selected.

### Boundary labels

- **D = DIAGNOSTIC PREVIEW:** protected, isolated, synthetic-data deployment for inspecting known gaps, not successful sign-in or complete business workflows. Requires explicit deployment authorization and verified isolation/configuration.
- **U = FUNCTIONAL UAT PREVIEW:** the affected real workflow in isolated non-production, including real test-provider effects where promised. A missing optional-material instance is different from a missing required capability.
- **P = PHASE-1 PRODUCT COMPLETENESS:** the complete mandatory feature/interaction set. A subset demo does not satisfy it.
- **R = PRODUCTION:** safe real-data operation, including authorization, recovery, provider configuration and operational proof.

The extra `Blocked boundary` column applies to the row's unresolved gap or required acceptance gate. `—` means no independent gap established in that retained concern, not that the system can ship. U is scoped to the affected journey; it is not a claim every gap prevents testing every other page. D normally excludes real confidential data: F02 is not permission to use such data in a so-called diagnostic deployment.
